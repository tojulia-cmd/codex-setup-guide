Codex: от редактора до своего бота

Пройди путь от первой задачи в редакторе до OpenClaw на сервере и Telegram-бота, который понимает голос. По-русски, с готовыми запросами и проверками результата.

Windows и VS CodeCodex и GitHubUbuntu и OpenClawTelegram
Начать с первой главы

Если что-то уже настроено, выполни проверку и переходи дальше. Повторная установка ради галочки не нужна. Разбей прохождение на несколько подходов: оплата, входы и ожидание провайдера могут занять дополнительное время.

Сначала различай три места. Промпт отправляем в чат Codex. Команды Windows выполняем в PowerShell на компьютере. Команды Ubuntu выполняем в терминале после SSH-входа на сервер. Над каждым блоком указано, куда его вставить.

Codex помогает выполнять действия, OpenClaw постоянно работает на сервере, GitHub хранит код. Подключение одного из них не означает, что остальные уже настроены. Сайт ничего не устанавливает сам.

Часть 01

Редактор и Codex

Результат: отдельная папка проекта открыта в VS Code, Codex отвечает и видит нужные файлы.

  1. Установи Visual Studio Code с сайта Microsoft, если его ещё нет. Найди Explorer, Extensions и Terminal → New Terminal.
  2. Создай общую папку VIBE CODING, а в ней отдельную папку для каждого проекта. В VS Code нажми File → Open Folder и открой именно папку проекта. Существующий проект заново создавать не нужно.
  3. В Extensions найди Codex от OpenAI, идентификатор openai.chatgpt. Установи расширение. Если значка нет, открой палитру Ctrl+Shift+P и найди Codex: Open Codex Sidebar.
  4. Выбери вход через ChatGPT и заверши его в браузере под своим аккаунтом. Доступ зависит от аккаунта, тарифа и политики организации. Ключ API для этого маршрута не нужен.
  5. Отправь первый запрос ниже. На этом шаге достаточно чтения проекта.
В чат Codex · первый запрос
Общайся со мной по-русски, простыми словами. Назови текущую рабочую папку. Прочитай AGENTS.md и PROJECT.md, если они есть. Кратко объясни, что находится в проекте, и предложи одну небольшую учебную задачу. Пока ничего не изменяй и не устанавливай.

IDE и CLI. IDE — редактор с панелью Codex. CLI — Codex в обычном терминале. Для начала достаточно расширения; терминальный вариант нужен только если ты выбираешь этот способ работы. Команды со слэшем из главы 3 относятся прежде всего к CLI.

Дополнительно: отдельный Codex CLI

Установи Node.js из следующей главы, затем в PowerShell:

PowerShell · установка CLI из npm
npm.cmd install -g @openai/codex
codex --version
codex login

Запускай codex из папки нужного проекта. Если CLI уже поставляется с приложением или расширением, сначала проверь доступную версию; установка второй копии необязательна. Если PATH ещё не обновился, открой новый терминал.

Часть 02

Окружение и защита

Результат: версии программ известны, область записи ограничена, дополнительная защита проверена. Песочница ограничивает действия технически; AGENTS.md задаёт правила поведения. Одно не заменяет другое.

Проверь программы до установки

PowerShell · безопасная проверка версий
node --version
npm.cmd --version
git --version
ssh -V

Если Node.js отсутствует, установи LTS с официального сайта и открой новый терминал. Если нет Git — используй Git for Windows. Версию Node сопоставляй с требованиями конкретного проекта, а не с требованием «всегда самая новая». В PowerShell команда npm.cmd позволяет использовать npm без изменения политики запуска скриптов.

В чат Codex · проверка окружения
Проверь node, npm, Git и OpenSSH. Покажи версии и совместимость с этим проектом. Если чего-то не хватает, предложи официальный источник установки. Не переустанавливай работающие программы и не меняй глобальную ExecutionPolicy.

Выбери границы доступа Codex

Для обычного проекта начни с режима Auto / Workspace: запись в рабочую папку и запросы при необходимости выхода за разрешения. Для ознакомления используй Read Only. Названия в расширении или приложении могут отличаться; проверь описание выбранного режима.

PowerShell · пример запуска установленного CLI
codex --sandbox workspace-write --ask-for-approval on-request

На Windows используется собственная песочница Codex; её доступность зависит от версии Windows и настроек устройства. WSL не нужен для обычного старта. Настройку песочницы выполняй по официальной инструкции Windows. После изменения режима начни новую сессию и проверь фактические разрешения.

Запись и чтение — разные границы. workspace-write не обещает скрыть все файлы вне проекта. Доступ к чтению, сети, приложениям и MCP проверяется отдельно. Full Access снимает ограничения песочницы; установка DCG не делает этот режим эквивалентным изоляции.

DCG: дополнительный фильтр команд

Destructive Command Guard анализирует команды до выполнения. Поддержка Codex и формат хуков зависят от версии. Сначала прочитай инструкцию проекта, затем проверяй установку. Хук — программа, запускаемая на определённом событии агента.

В чат Codex · проверка DCG
Проверь DCG для установленной версии Codex по официальному репозиторию destructive_command_guard. Сначала выполни dcg --version и dcg doctor. Если он отсутствует — предложи установку из официального источника. Если хук не доверенный, объясни, где мне подтвердить его в Codex; не подделывай запись доверия. Проверь анализ безопасной и опасной тестовых строк через dcg test, не исполняя опасную команду. Отдельно укажи, проверен ли реальный вызов хука для инструмента нашей сессии, включая PowerShell.

dcg doctor должен подтверждать регистрацию и доверие в Codex. Успешный анализ тестовой строки доказывает работу анализатора, но не вызов хука в каждой оболочке. Не проверяй защиту настоящим удалением файлов.

«Замок», резервные копии и проверка границ

Скрипты и settings.json из инструкций Claude нельзя переносить в Codex без проверки формата. Для запрета чтения нужны поддерживаемые ограничения доступа, а для наиболее строгого разделения — отдельная среда или учётная запись с нужными правами.

В чат Codex · безопасный аудит границ
Покажи фактический режим доступа и область записи текущей сессии. Не меняй разрешения. Предложи проверку записи в проект и отказа вне него с новым пустым тестовым файлом: только уникальное имя, без перезаписи существующих данных. Для чтения используй заранее созданный безобидный образец, а не мои секреты. Не расширяй права ради прохождения проверки. Отдельно проверь доступы MCP и браузера. Если тест не выполнялся, не называй изоляцию подтверждённой.

Перед большой задачей сохраняй рабочий код в Git. GitHub хранит только отправленные коммиты; незакоммиченные файлы, .env и данные браузера нуждаются в отдельной резервной копии. В Windows настрой подходящую резервную копию, например «Историю файлов» с отдельным диском.

Часть 03

Управление агентом

Результат: ты умеешь задавать задачу, выбирать модель, смотреть изменения и сохранять постоянные правила.

В расширении найди новый диалог, историю, выбор модели, уровень размышления, разрешения и просмотр diff — изменённых строк. Используй открытый файл, выделение и упоминания @ там, где они доступны. Сначала попроси Codex подтвердить, какой файл он видит.

ЗадачаВ Codex CLIВ редакторе
Модель и глубина размышления/modelСелектор модели и reasoning
Контекст и параметры сессии/statusИндикатор контекста и настройки сессии
Разрешения/permissionsМеню доступа / разрешений
Новая задача/newНовый диалог
Сжатие длинного диалога/compactАвтоматическое сжатие или доступная команда
Возврат к разговору/resumeИстория диалогов
Проверка правок/review, git diffDiff и проверка изменений

Это команды CLI, а не обещание одинакового меню во всех клиентах. Набери / в своём клиенте и посмотри доступные команды. Не переноси /effort, /doctor и /rewind из Claude как универсальные команды Codex. Откат сначала обсуждай по конкретному diff; не используй массовый сброс рабочей папки.

Создай правила AGENTS.md

Общие правила лежат в %USERPROFILE%\.codex\AGENTS.md, правила проекта — в его корне. Codex учитывает иерархию инструкций. Существующие файлы нужно дополнять, сохраняя правила и чужие изменения. PROJECT.md — удобная документация проекта, но не обязательный встроенный файл Codex.

Образец файла AGENTS.md · адаптируй под проект
# Правила проекта
- Общайся по-русски, незнакомые термины объясняй коротко.
- Перед работой прочитай PROJECT.md и проверь git status.
- Для задачи из нескольких шагов дай краткий план и способ проверки.
- Меняй только то, что относится к запросу. Сохраняй чужие правки.
- Не публикуй ключи, пароли, токены и персональные данные.
- Не удаляй пользовательские файлы и не переписывай историю Git без отдельного согласования.
- Для тестов используй вымышленные данные и отдельный профиль браузера.
- В отчёте разделяй выполненные проверки и то, что осталось непроверенным.
- Обновляй PROJECT.md при изменении поведения или запуска.
В чат Codex · персонализация правил
Прочитай существующие общие и проектные AGENTS.md. Помоги адаптировать правила к этому проекту, не затирая действующие ограничения. Если неясно назначение, спроси меня. Объясни, какие инструкции действуют, и сохрани сведения об устройстве проекта в PROJECT.md. Не переноси правила Claude и не меняй настройки доступа автоматически.

Одна самостоятельная задача — один диалог. Сохраняй важные решения в документации: история и сжатие контекста не заменяют знание о проекте. Для сложной задачи можно выбрать более глубокое размышление, но уровень должен поддерживаться моделью; расход лимитов и время ответа могут увеличиться.

Часть 04

GitHub, навыки и браузер

Результат: агент может работать с выбранным репозиторием, пользоваться нужными навыками и проверять страницы.

Подключи GitHub с нужными правами

  1. Создай аккаунт на GitHub, если его нет. В Settings → Password and authentication включи 2FA и сохрани резервные коды вне репозитория.
  2. Сначала проверь существующее подключение GitHub в Codex. Попроси показать логин и прочитать выбранный репозиторий. Настроенный коннектор, MCP и GitHub CLI — разные способы доступа.
  3. Для локального Git и управления Pages можно использовать GitHub CLI и вход через браузер. Если нужен PAT, выбирай минимальные права и выбранные репозитории, указывай срок действия. Не отмечай все права подряд.
PowerShell · если GitHub CLI уже установлен
gh auth status
gh api user --jq .login

Если вход отсутствует, запусти gh auth login --hostname github.com --web и заверши авторизацию в браузере. Не отправляй PAT в чат и не вставляй его в командную строку, исходники или URL. Чтение репозитория не доказывает право включать Pages; для этого нужны отдельные права управления.

В чат Codex · проверка GitHub и публикации
Проверь доступ к GitHub доступным подключением. Покажи только логин, выбранный репозиторий и фактические права. Не выводи токены. Перед коммитом покажи список файлов и git diff --staged. Для публикации статической инструкции создай отдельный публичный репозиторий с index.html и .nojekyll, включи GitHub Pages из main, корень /. Не публикуй мой личный аудит и файлы других проектов. После публикации проверь успешный deployment и открытие сайта.

Навыки: проверь имеющиеся

Навык — папка с SKILL.md и дополнительными материалами. Типовые пути Codex: %USERPROFILE%\.agents\skills для пользователя и .agents/skills для проекта. Приложение может предоставлять встроенные и подключённые навыки отдельно. Файл на диске и реально доступный в сессии навык — разные проверки.

В чат Codex · инвентаризация навыков
Перечисли навыки, доступные в этой сессии, и отдельно найденные пользовательские SKILL.md. Для текущего проекта предложи только необходимые. Проверь openclaw-docs, если будем работать с OpenClaw. Не устанавливай дубликаты и не запускай сторонние установщики без изучения источника.

Если openclaw-docs уже установлен, используй его и проверку актуальности. Если нет, попроси Codex читать официальную документацию OpenClaw напрямую. Не устанавливай навык из случайного архива ради совпадения с курсом.

Дополнительно: Superpowers для Codex

В актуальном README автора указан официальный каталог плагинов. В приложении Codex открой Plugins, найди Superpowers в разделе Coding и нажми «+», затем следуй подсказкам. В Codex CLI открой /plugins, найди superpowers и выбери Install Plugin. Если плагин не доступен в твоём клиенте, используй обычный план и проверки Codex.

Начни новую сессию и проверь наличие навыков плагина. Установка в Claude не означает установку в Codex. Старый путь .codex/INSTALL.md на дату проверки возвращает 404; его нельзя подставлять в установочный промпт. Команды /brainstorm и /execute-plan не являются обязательными встроенными командами Codex.

MCP и проверка браузером

MCP подключает инструменты и данные внешнего сервиса. Вначале используй уже доступные подключения. Дополнительный Playwright MCP нужен, только если браузерного инструмента нет и он необходим задаче. Наличие пакета Playwright в проекте само по себе не подключает MCP.

PowerShell · дополнительный MCP для Codex CLI
codex mcp add playwright -- npx.cmd -y @playwright/mcp@latest
codex mcp list

Команда загружает и запускает официальный пакет Playwright MCP из npm; используй её только после проверки источника и при необходимости. После подключения открой новую сессию и попроси открыть тестовую страницу. Статус enabled в списке означает настройку, а успешное открытие страницы — проверку работы. Для создания и удаления тестовых данных используй отдельный профиль, не личный браузер.

Часть 05

Рабочий сервер

Результат: известно, где работает OpenClaw, кому принадлежит сервер и хватает ли ему ресурсов. Если сервер уже есть, начинай с аудита, а не с покупки.

  1. В панели своего хостинга проверь существующие машины, систему, ресурсы и резервные копии. Не выключай VPN или другие работающие сервисы.
  2. Для нового сервера выбери поддерживаемый Linux; для соответствия маршруту курса подходит Ubuntu 24.04. Требования установленной версии OpenClaw сверяй с его документацией.
  3. Оцени ресурсы по нагрузке: браузерная автоматизация и несколько ботов требуют больше памяти, чем один текстовый бот. Указанные в курсе 4 ядра, 8 ГБ RAM и 120 ГБ диска — ориентир его сценария, а не доказанный универсальный минимум.
  4. Сравни текущий тариф, резервные копии, регион, условия доступа провайдеров моделей и возможность оплаты. Цены и доступность меняются; не покупай сервер только по старой таблице.
  5. Сохрани адрес, имя пользователя и способ входа в менеджере паролей. Пароль вводи в терминале или панели, не в чате с агентом.
В чат Codex · аудит имеющегося сервера
Помоги проверить мой существующий сервер без изменений. Сначала найди согласованный SSH-алиас, не читай приватные ключи и не выводи секреты. На сервере проверь систему, CPU, память, свободный диск, действующие сервисы и наличие OpenClaw. Не выполняй обновление системы, установку, перезапуск или покупку. Скажи, подходит ли сервер под одного Telegram-бота и какие ограничения остаются для нескольких связок. Если подключение не настроено, спроси способ доступа.
Отсутствие SSH-настроек на компьютере не доказывает отсутствие сервера. Для проверки можно использовать существующее приложение подключения или консоль хостинга. Статус «сервер проверен» ставим только после фактического доступа.
Часть 06

Вход по SSH-ключу

Результат: короткая команда открывает нужный сервер, приватный ключ остаётся на компьютере.

Проверь существующий ключ

PowerShell · список файлов, без содержимого ключей
Get-ChildItem -LiteralPath "$env:USERPROFILE\.ssh" -ErrorAction SilentlyContinue

Файл с .pub — публичный ключ, его можно добавить на свой сервер. Файл без этого окончания — приватный; его нельзя отправлять агенту, на GitHub или в чат. Если ключа нет, создай его в PowerShell:

PowerShell · создание ключа, только если подходящего ещё нет
ssh-keygen -t ed25519

Если программа предлагает перезаписать существующий ключ — остановись. Passphrase защищает ключ дополнительной фразой; при её использовании для удобного входа может понадобиться SSH-agent.

Добавь публичную часть и короткое имя

Добавь содержимое id_ed25519.pub через раздел SSH keys хостинга или в ~/.ssh/authorized_keys нужного пользователя на сервере. В Windows ssh-copy-id обычно не установлен: команда из Linux-инструкции не обязательна. Первое подключение и отпечаток сервера сверяй с панелью хостинга; не отключай проверку host key.

Создай или дополни %USERPROFILE%\.ssh\config, сохрани остальные записи. Подставь реальные адрес и пользователя вместо примеров:

Файл .ssh/config на Windows · пример
Host my-server
    HostName SERVER_ADDRESS
    User SERVER_USER
    IdentityFile ~/.ssh/id_ed25519
    IdentitiesOnly yes
PowerShell · проверка доступа
ssh my-server

Успех: появился терминал нужного сервера. Если спрашивается пароль учётной записи сервера — вход по ключу ещё не подтверждён. Запрос passphrase самого ключа — другой запрос, он допустим.

В чат Codex · настройка SSH без потери доступа
Помоги настроить SSH по ключу в Windows. Сохрани существующие ключи и записи config. Публичный ключ добавим через хостинг или существующий вход, приватный не читай. Проверь алиас my-server. После успешного входа во втором независимом терминале предложи отключение парольного входа и root-доступа по моей ситуации. Перед изменением sshd проверь конфигурацию, сохрани рабочую сессию и способ восстановления через консоль хостинга. Не выполняй отключение до проверки резервного доступа.

Предпочтителен отдельный пользователь с необходимыми правами. Если хостинг выдал только root, сначала подготовь обычного пользователя и проверь его доступ. Изменение SSH — отдельный шаг: потеря доступа не исправляется повторной установкой клиента на Windows.

Часть 07

OpenClaw и панель управления

Результат: OpenClaw установлен, Gateway работает после выхода из SSH, панель доступна через защищённое соединение. Gateway — постоянно работающий процесс, который связывает модель, инструменты и каналы.

Сначала узнай состояние и версию

Терминал Ubuntu · после ssh my-server
openclaw --version
openclaw gateway status
openclaw doctor

Если команда не найдена, проверь PATH и существующую установку. Не запускай переустановку автоматически. Для нового сервера используй официальную инструкцию установки, прочитанную на момент работы, и требования к Node.js.

В чат Codex · подготовка и установка
Используй openclaw-docs: проверь актуальность документации. Подключись к согласованному серверу. Сначала только аудит версии, системы, ресурсов, PATH и существующей установки. Если OpenClaw отсутствует, предложи точный способ установки из официального источника. Загруженный скрипт сначала сохрани и изучи; не используй curl | sh. Не обновляй всю ОС, не выполняй autoremove, перезагрузку или замену действующих сервисов без отдельного согласования. Существующие настройки и данные сохрани. После установки покажи версию и проверки без секретов.

Пройди мастер и включи фоновый сервис

Терминал Ubuntu · интерактивный мастер
openclaw onboard

Мастер меняется между версиями. Читай подсказки; выбери локальный Gateway и доступ только через loopback. Для подробных настроек в актуальной документации есть openclaw onboard --classic. Авторизацию модели завершишь по главе 8; готовность модели пока не отмечай.

Если фоновый сервис ещё не установлен и мастер его не создал, актуальная последовательность:

Терминал Ubuntu · только если сервис ещё не настроен
openclaw gateway install
openclaw gateway start
openclaw gateway status
openclaw health

На Linux проверь, под каким пользователем запущен сервис и сохраняется ли работа после выхода из SSH. Для systemd user-service может потребоваться linger для этого пользователя. Не включай его для root по шаблону и не дублируй уже работающий сервис. Сервис может стартовать с задержкой; сначала повтори проверку, а не установку.

Открой панель через туннель

PowerShell на компьютере · оставить терминал открытым
ssh -N -L 18789:127.0.0.1:18789 my-server

Открой http://127.0.0.1:18789/. Здесь 18789 — типичный порт; проверь фактический порт в статусе. Если локальный порт занят, используй, например, 18790:127.0.0.1:18789 и адрес http://127.0.0.1:18790/. Закрытие туннеля закрывает доступ с компьютера, но не удаляет данные и не выключает Gateway.

Не открывай порт Gateway всему интернету ради панели. Введи токен локально по инструкции установленной версии. Не проси агента присылать ссылку с токеном в чат: такая ссылка содержит секрет и может попасть в историю, логи или скриншоты.
В чат Codex · проверка панели
Проверь Gateway и его bind-адрес по документации установленной версии. Помоги открыть SSH-туннель и панель на моём компьютере. Токен не считывай в ответ и не включай в URL для чата; подскажи, как ввести его локально. Проверь фоновый сервис и работу после выхода из SSH. Раздели проблемы установки, сервиса, авторизации модели и туннеля.
Часть 08

Подключение модели

Результат: OpenClaw авторизован отдельно, выбранная модель отвечает в панели. Вход в Codex на Windows не доказывает вход OpenClaw на сервере.

В актуальной документации OpenClaw для OpenAI используется провайдер openai. Есть авторизация через ChatGPT/Codex, отдельная Sign in with ChatGPT и API key с биллингом OpenAI Platform. Выбирай подходящий доступ своему аккаунту. Подписка не означает безлимитную работу или доступ ко всем API.

Терминал Ubuntu · проверка и авторизация
openclaw models status
openclaw models auth login --provider openai

Пройди предложенный вход в своём браузере. Для удалённого сервера документация предусматривает device-code; уточни доступные методы через помощь установленной версии. Не пересылай файлы авторизации с компьютера на сервер вручную и не публикуй коды.

Терминал Ubuntu · доступный каталог
openclaw models list --provider openai
openclaw models status

Исходный курс предлагает openai/gpt-6-astra. Сначала проверь, доступна ли эта модель конкретному аккаунту и установленной версии. Если нет, выбери из фактически доступных моделей после объяснения различий. Перечень каталога ещё не доказывает право вызова: нужен тестовый ответ.

В чат Codex · подключение модели без догадок
По актуальному openclaw-docs проверь авторизацию OpenAI в OpenClaw на сервере. Помоги выполнить вход через мой аккаунт ChatGPT, не показывая секреты. Сначала проверь доступность openai/gpt-6-astra; если недоступна, покажи доступные варианты и предложи подходящий. Проверь поддерживаемый уровень размышления high и выставь его для выбранной модели только если поддерживается. Не меняй способ оплаты на API key без согласования. Попроси меня отправить тест в панели и после результата проверь статус и ошибки.

Уровень размышления в OpenClaw настраивается отдельно от Codex в редакторе. high — запрос на более глубокое рассуждение; точное поведение зависит от модели. Значения low, medium, high и более высокие уровни поддерживаются не везде одинаково. Используй /think high в поддерживаемом чате OpenClaw или актуальную настройку по документации.

Проверка: в панели спроси «Ответь одним предложением: что такое SSH?» и дождись содержательного ответа. Лимиты проверяй в своём аккаунте и статусе провайдера; утверждение «Plus работает ровно пять часов в неделю» здесь не используется.

Часть 09

Telegram и голосовые

Результат: личный бот отвечает владельцу на текст, а голосовое распознаётся и обрабатывается.

Создай и привяжи бота

  1. Открой @BotFather, проверь точное имя аккаунта. Отправь /newbot, выбери имя и уникальный username с окончанием bot.
  2. Сохрани полученный токен в менеджере паролей. Введи его в настройках Telegram-канала OpenClaw или через предусмотренный секретный ввод. Не вставляй токен в чат Codex.
  3. Оставь политику личных сообщений pairing — разрешение после привязки. Открой своего бота, нажми Start и отправь сообщение. На сервере проверь заявку и подтверди только свой код.
Терминал Ubuntu · проверка канала и привязка
openclaw channels status --probe
openclaw pairing list telegram
openclaw pairing approve telegram YOUR_PAIRING_CODE

В последней строке замени YOUR_PAIRING_CODE своим действующим кодом, не запускай её буквально. В актуальной документации есть переменная TELEGRAM_BOT_TOKEN для аккаунта по умолчанию и tokenFile для конфигурации. Выбери подходящий способ хранения с агентом, не печатая значение. Команда channels login telegram для этого не используется.

В чат Codex · подключение Telegram
Проверь по openclaw-docs настройку Telegram установленной версии. Подготовь канал с политикой pairing. Токен я введу сам локально или в панели; не проси его в чат, не печатай значение и не помещай его в команды с историей. Помоги проверить заявку моего аккаунта и подтвердить её. Затем я отправлю вымышленное тестовое сообщение. Не добавляй бота в группы и не открывай доступ всем пользователям.

Добавь распознавание голоса

Речь сначала переводится в текст, затем модель отвечает на него. Это отдельная возможность со своими учётными данными и лимитами. Маршрут курса — Groq; проверь актуальные условия и доступность в консоли Groq. Бесплатный тариф, если он доступен, имеет ограничения.

Актуальная документация OpenClaw описывает отдельный официальный плагин Groq и общую настройку аудиомоделей. Перед установкой проверь, не установлен ли плагин:

Терминал Ubuntu · установка только при отсутствии плагина
openclaw plugins install @openclaw/groq-provider

Ключ GROQ_API_KEY введи локально в защищённую конфигурацию окружения сервиса, например в ~/.openclaw/.env пользователя Gateway. Не показывай содержимое файла в выводе. Переменная в текущем SSH-терминале может не попасть в уже работающий systemd-сервис.

Фрагмент конфигурации OpenClaw · объединить с существующей
{
  "tools": {
    "media": {
      "models": [
        { "provider": "groq", "capabilities": ["audio"] }
      ],
      "audio": { "enabled": true, "echoTranscript": true }
    }
  }
}

Это фрагмент, а не замена всего файла: сохрани существующие модели изображений, видео и другие настройки. Здесь модель аудио выбирается плагином; на дату проверки его стандартная модель — whisper-large-v3-turbo. В исходнике указан whisper-large-v3; при необходимости выбирай конкретную модель по актуальному каталогу. echoTranscript включает показ расшифровки, который по умолчанию может быть выключен.

В чат Codex · голосовые через Groq
Используй актуальный openclaw-docs. Проверь плагин Groq и настройку tools.media.models с возможностью audio. Ключ я внесу локально, не считывай его в ответ. Убедись, что окружение доступно пользователю Gateway. Сохрани существующую конфигурацию, добавь Groq для аудио и показ расшифровки, не меняя провайдера обычного чата. После проверки конфигурации перезапусти сервис, если менялось окружение. Я отправлю короткое вымышленное голосовое; проверь фактическую расшифровку и ответ, а не только отсутствие ошибок при запуске.

Проверка: запиши «Добавь в учебный список задачу проверить резервную копию» без реальных данных. Должны прийти распознанный текст и ответ. Если голос не работает, отдельно проверь получение файла, плагин, ключ в окружении сервиса и лимиты. Не отправляй запись нескольким провайдерам незаметно. Платный резерв OpenAI подключай отдельно после согласования тарифа и маршрута данных.

Часть 10

Финальная проверка и починка

Результат: ты знаешь, какие части контура работают, где искать ошибку и как вернуться к работе после закрытия терминала.

На сервереЧто проверяем
openclaw --versionУстановленная версия
openclaw doctorДиагностика без автоматического исправления
openclaw gateway statusСервис и доступность Gateway
openclaw healthТекущее здоровье
openclaw models statusАвторизация моделей и доступные сведения о лимитах

openclaw logs --followЖивые логи, выход Ctrl+C; перед отправкой скрыть секреты

Если бот молчит

  1. Проверь, отвечает ли модель в панели. Если панель недоступна, сначала различи закрытый SSH-туннель и остановленный Gateway.
  2. Проверь Gateway, затем модель и канал командами выше. Сохрани точную ошибку без ключей и личных сообщений.
  3. Если панель отвечает, а Telegram нет — проверь токен, сеть, pairing и статус канала. Если текст работает, а голос нет — проверь аудиоплагин и его учётные данные.
  4. Исправляй найденную причину. openclaw doctor --fix изменяет настройки; сначала изучи диагностику и резервную копию. openclaw gateway restart перезапускает сервис, но не восстанавливает истёкший доступ к модели.
В чат Codex · диагностика без переустановки
Бот перестал отвечать. Проверь документацию установленной версии OpenClaw и проведи диагностику по слоям: SSH, Gateway, модель, Telegram, аудио. Начни с чтения статусов и обезличенных ошибок. Не переустанавливай приложение, не удаляй данные и не запускай doctor --fix без объяснения, что он изменит. После исправления проверь именно сломавшийся сценарий и отдельно сообщи, что осталось непроверенным.

Контрольный проход

Закрой старую SSH-сессию, открой новую, проверь Gateway и заново подними туннель. Отправь тест в панели, текст и голосовое в Telegram. Это проверка работы после выхода из терминала; загрузку после перезагрузки сервера нужно проверять отдельно в согласованное время.

Что дальше. Если обязательные проверки пройдены, инфраструктура готова к следующим учебным связкам. Каждую новую интеграцию проверяй отдельно. Галочки в этой тетради не предоставляют доступ к сервисам и не являются автоматическим подтверждением их состояния.
